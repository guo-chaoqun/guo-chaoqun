## 🚀 项目作品集

### 项目一 · 电商智能客服 · AI 评测体系（505 用例 + 双通道判分）

> 完整实践了 AI 效果验证的全流程：怎么定义"答得好"、怎么出题考模型、怎么找到错因、怎么证明改进是真的。

![电商客服 RAG 评测 dashboard](img/rag-dashboard.png)

- 📊 **量化结果**：通过率 91.5% → 97.0%，幻觉率 8.3% → 2.6%，违规率 8.9% → 0
- 🧩 **评测集构建**：505 条用例 × 5 类测试（功能/边界/违禁/多轮/对抗）× 3 级难度，每条 17 字段、case_id 跨版本追踪
- ⚖️ **双通道判分**：确定性规则预检 + LLM-as-a-Judge（裁判 v4.0→v4.4 迭代，人工盲评校准）
- 🔁 **复评基准**：同一裁判口径重评历史版本，消除评测工具漂移——旧裁判系统性低估幻觉率（3.0% → 真实 8.3%）
- 🔍 **Bad Case 归因**：8 类根因，72.1% 集中于分类误路由，按「影响面 × 修复难度」排优先级

## 🧠 我的评测方法论

- **有评测才有迭代**：任何 AI 产品，先搭评测体系再动功能
- **裁判本身也要被验证**：LLM 裁判需人工盲评校准 + 偏置探针（位置偏置 / 量表遵从性 / 裕度分布）
- **Bad Case 归因到根**：不看"错了几条"，看"为什么错、错得集不集中"
- **改动必回归**：黄金集 + 质量门禁，防止修好这里、弄坏那里
