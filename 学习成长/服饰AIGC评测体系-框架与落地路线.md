## 一、行业地图：服饰 AIGC 评测评什么

### 1.1 三个评测对象

```
用户 Query（"梨形身材，周末约会，别太露"）
   │
   ├─ 对象① 结构化文本回复：档案卡、推荐单品、配色分析、导购词
   │         评：意图理解对不对、内容相不相关、完不完整、有没有编造
   │
   ├─ 对象② 搭配方案本身：这几件衣服搭在一起合不合理、好不好看
   │         评：色彩和谐、廓形平衡、身形修饰、场合契合、风格统一
   │
   └─ 对象③ 生成图 / 虚拟试穿：效果图像不像、真不真、美不美
             评：文本-图像对齐、服装保真、画质、美学、身份保持
```

### 1.2 AIGC 图像评测的工业界三维共识

学术界和工业界（文生图质量评估综述、NTIRE 2025 挑战赛）已收敛为三大维度：

1. **对齐 Alignment（相关性）**：提示词里的颜色、款式、数量、空间关系有没有生成出来 → CLIPScore、VQAScore、TIFA
2. **感知质量 Perception（真实性）**：有没有畸变、糊不糊、像不像照片 → FID、IQA 画质模型
3. **美学 Aesthetics（好不好看）**：色彩和谐、构图、光影 → ImageReward、HPSv2、VIEScore、LAION-Aesthetics

> 记忆：**"对不对、真不真、美不美"**——三问对应三维。

### 1.3 服饰领域的学术评测体系（知道名词就是内行）

**搭配合理性方向（对象②）：**
- **Polyvore Outfits**：行业标准公开数据集（nondisjoint 划分约 5.3 万套训练 + 1 万套测试），三个标准任务：
  - **CP（Compatibility Prediction）**：整套搭不搭，指标 **AUC**
  - **FITB（Fill-In-The-Blank）**：挖掉一件选最合适的，指标 **Accuracy**
  - **CIR（Complementary Item Retrieval）**：给一件找搭配，指标 **Recall@K**
- **TATTOO（2025）**：把"美学感知"显式加入搭配推荐
- 学术共识：**"搭不搭"没有公开真值**——Polyvore 的标注是点赞/共现的隐式信号，不是美学裁判，所以人类专家 Rubric 仍不可替代

**虚拟试穿方向（对象③）：**
- **VTBench**：第一个分层试穿基准，5 个维度——整体画质、纹理保持、复杂背景一致性、身份保持等
- **VTONQA**：8132 张图 × 11 个试穿模型，人工 **MOS 主观分**三维度——**clothing fit 合身度 / body compatibility 身体协调性 / overall quality 整体质量**
- **Styletailor（AAAI 2026 Oral）**：VQAScore 评风格一致性 + IQAScore 评视觉质量 + 面部相似度
- 自动指标：**CLIP-I**（生成图 vs 衣服原图，服装保真）、**CLIP-T**（生成图 vs 文本，语义对齐）

### 1.4 自动裁判怎么验证它靠谱（行业做法）

- **人工 MOS（Mean Opinion Score）**：多人对同一批图 1-5 分打分，取均值作为"金标准"
- **衡量相关性**：自动模型分 vs 人工 MOS 的 **SRCC（斯皮尔曼等级相关）/ PLCC（皮尔逊线性相关）/ Kendall**——NTIRE 2025 对齐赛道主评分 = 0.5×ACC + 0.25×(SRCC+PLCC)
- 一个诚实的行业事实：VIEScore 与人工判断相关性约 0.31，而**人与人之间也才 0.42**——审美自动评测至今没有"银弹"，**"自动分 + 人工抽检校准"是公认的落地形态**

### 2.2 主观审美层（做过两轮实验，有边界清晰的结论）

| 资产 | 内容 |
|---|---|
| 三臂对照实验 `three_arms.py` | 五维判官：色彩和谐 / 场合契合 / 温度得体 / 整体协调 / 专业感；30 对盲评结果 26 平 / 2 甲 / 2 乙 |
| 设计五维 Rubric | **廓形平衡 / 层次叠穿 / 身形扬长避短 / 风格统一度 / 组合逻辑**（各 1/3/5 分锚点） |
| v1/v2 验证记录 | `design-judge-rubric.md`：一致率 0%→50%，但校准硬门未过；**实证三大失效机制：位置偏置 87.5%→75%、量表违规（打出 8-9 分）、裕度不足（3/4 对分差≤1/50）** |
| 结论 | 当前模型对设计维度的自动评判**不可靠**；报告里自己写了重启方向：成对比较多轮投票 / 多判官集成 / 真实用户偏好监督校准 |

> ⭐ **这个实验的价值**：不只是"用大模型当裁判打分"，而是**实证了裁判会在审美问题上骗人**——用双序交换抓到 87.5% 位置偏置，给出了有边界的否定结论，并知道下一步该用人类偏好训练的专门模型（ImageReward / VIEScore）而不是继续改措辞。客服项目的"裁判三探针"正是从这个实验长出来的。

2. **结构化回复相关性评测**：导购词只评了"可搜性"等代理指标，没评"回复 vs 用户需求"的相关性

## 三、正式框架：九层穿搭 AIGC 评测体系（L0-L8）

> ⚠️ **先分清两个视图，这是本次审计修正的核心逻辑：**
>
> - **下面的 L0-L8 是「对象/职能视图」——回答"评什么、谁来评"**，各层是并列模块，不是先后步骤
> - **真正动手时要走「搭建流程视图」——回答"先做什么后做什么"**，行业通用闭环（Define→Test→Diagnose→Fix）落到这个项目是：
>
> ```
> P0 定目标：业务目标→可测指标→评测边界（评什么/不评什么）→评测频率
> P1 建金标准：真实 Query 采样 + 分层分布设计 + 期望标注（重合样本人工多标，算一致性）
> P2 配判分：每层按"规则 → 专用模型 → 人评"选通道，自动裁判必须先过人工相关性校准
> P3 跑基线：拿到第一版总分/维度分/混淆矩阵，建立对照
> P4 归因：用 L5 五分类标 badcase，按影响面×修复难度排优先级
> P5 优化验证：推动算法侧改 → 同一基准回归 → 配对检验确认提升真实
> P6 门禁与回流：黄金集分层门禁 + 线上 badcase/用户负反馈持续回流评测集
> ```
>
> 学习时先读 L0-L8 建立地图，动手时严格按 P0-P6 走；L6 标注质量是**贯穿 P1/P2 的基础设施**，不是第六步；L0（目标）和 L8（横切）分别在流程的起点和全程起作用。
>
> 每层写明：评什么、用什么方法、行业参照、我的现状和补法。

### L0 目标与口径层（P0，所有层之前必须先定）

**评什么**：这次评测为谁服务、证明什么、怎么算"过"。

- **业务目标 → 北极星指标**：如"提升搭配方案采纳率/二调成功率"，评测指标要能挂到业务目标上，不能为评测而评测
- **评测边界**：本轮评什么、不评什么（如 D1 只评 Query 理解，不评生成图）；一次只动一个变量
- **通过标准（放行阈值）**：每个维度多少分算过、版本放行规则——直接复用我在穿搭项目的三层门禁实践：结构约束硬拦、质量比率观测（任一维掉 >5pp 才拦）、零交付直接红
- **评测频率**：日常快检（小黄金集）→ 版本合并前（标准集）→ 大版本前（全量），对应我已有的 Gate 分层
- **参照**：行业评测实践的 Define 阶段——"把质量要求写成可测试的条款，先想清楚什么失败代价最高"（arXiv 2601.22025）；国际电信联盟 ITU-T F.748.77（2025.12）基础模型评估工作流也以"评估目标与环境准备"为第一步

### L1 Query 意图理解评测（JD 核心，缺口①）

**评什么**：用户那句话/那张档案，系统有没有读懂。

- **意图分类体系**（先定 taxonomy）：要搭配方案 / 要购物指南 / 要衣橱排期 / 要试穿 / 闲聊兜底；服饰属性抽取：场合（约会/通勤/婚礼…）、风格、身材诉求（扬长/避短部位）、硬约束（不要黑色/不露腿）、预算
- **评测方法**：人工标注 Query 期望意图 → 跑系统意图识别 → **准确率 + 混淆矩阵**（重点看边界混淆，如"想要显瘦的宽松款"是风格诉求还是版型诉求）
- **改写评测**（JD 说"理解与改写逻辑"）：系统对模糊 Query 的改写是否保留原意——覆盖率、要点召回率（参照电商 Query Rewriting 论文的 coverage / token-recall / relevance 指标）
- **我的迁移路径**：客服项目"行为特征判定法"（咨询 vs 办理）直接迁移为"诉求 vs 约束 vs 闲聊"的行为分类
- **落地动作**：标 50 条真实 Query 的期望意图 → 跑一版 → 出混淆矩阵

### L2 结构化回复相关性评测（JD 核心，缺口②）

**评什么**：回复的内容对不对、全不全、是不是忠于用户档案。

- 维度设计（客服 7 维度的服饰裁剪版）：意图响应 / 场景契合 / 档案一致性（肤色体型不能答错）/ 信息完整（单品+配色+理由三要素）/ 忠实度（不能编造商品）/ 语气 / 合规
- **双通道**：规则预检（要素齐全性、must_not、与档案字段一致性核对）+ LLM 裁判（语义相关性）
- 裁判可靠性：直接上我的三探针（位置偏置/量表遵从/裕度分布）+ 人工盲评校准
- **落地动作**：30-50 条 Query-回复对 × 7 维度评分表

### L3 搭配审美评测（JD"主观审美→SOP"的核心）

**评什么**：这套衣服本身搭得好不好。

- **审美 Rubric 七维**（合并我已有的两版五维 + 三臂五维，1-5 分锚点）：
  1. 色彩和谐（已有规则层：标准色相角 + 明度/彩度）
  2. 廓形平衡（上松下紧等对比）
  3. 身形扬长避短（针对档案体型）
  4. 场合契合（通勤/约会/婚礼的着装规范）
  5. 风格统一度（正式度/材质/年代感一致）
  6. 层次与完整度（里中外层次、季节覆盖）
  7. 组合逻辑（每件为什么在这）
- **SOP 化四件套**（"主观变可执行"的标准答案）：
  1. 维度定义文档（每维度一句话）
  2. 1/3/5 分锚点 + 每档正反例图片（**正例反例比文字定义更重要**）
  3. 标注培训：试标 → 对答案 → 争议讨论 → 锁定标准
  4. 一致性度量：重合样本由多人独立打分后算系数——**2 人用 Cohen's Kappa，3 人及以上用 Fleiss' Kappa 或 Krippendorff's α**；若是多人排序结果则用 Kendall's W。≥0.8 表示标准可接受，**≥0.85 才放量给标注团队执行**
- **自动裁判定位（吸取 v1/v2 教训）**：
  - 确定性可算的归规则层（色彩、温度、场合禁忌）
  - 审美语义判分用**专门的偏好模型**（ImageReward / HPSv2 / VIEScore）或多模型集成投票，不用通用对话模型硬打
  - 一切自动分必须与人工 MOS 算 SRCC，相关不达标就只作"初筛"不作"判决"
- **我的现状**：Rubric 已有、失败机制已探明；**补法是建 50 套人工 MOS 金标准集 + 用 ImageReward 跑相关性验证**

### L4 生成图 / 试穿评测（缺口③）

**评什么**：效果图。按"对不对、真不真、美不美"三层：

| 层 | 指标 | 工具 | 说明 |
|---|---|---|---|
| 对齐 | 图 vs 提示词/档案 | **CLIP-T**、VQAScore | 要求的颜色/款式/场景有没有生成 |
| 保真 | 图 vs 用户上传的衣服 | **CLIP-I** | 衣服本身有没有被保留（试穿核心） |
| 画质 | 真实性/畸变 | IQA 模型、FID（批量时） | 多手指、融肢体等 |
| 美学 | 好看程度 | **ImageReward**、HPSv2、VIEScore | 人类偏好训练的分 |
| 试穿专项 | 合身/协调/整体 | 人工 **MOS 三维**（VTONQA） | clothing fit / body compatibility / overall |
| 身份保持 | 像不像本人 | 人脸相似度（有面部图时） | 试穿场景加分项 |

- **落地动作**：20-30 张效果图，三个自动分一条命令跑完 + 人工三维 MOS → 算 SRCC 验证自动裁判
- **细粒度对齐**：粗分之外还要按要素拆——颜色 / 品类 / 数量 / 空间关系是否逐项生成（TIFA 式问答核查），一个总分看不出"颜色对了但款式错了"
- **安全与隐私**：
  - 用户上传的是**真人照片**：人脸/人体图像的存储加密、授权范围、生成图不得用于训练
  - **身体意象风险**：输出不得出现身材羞辱、焦虑暗示（"你太胖所以要遮"类表述），我项目里"量感只做软消费、不收体重、不做硬门槛"的设计正是此考量
  - 生成图合规：不得走光/色情化/未成年人不当呈现，需专项对抗集
  - 隐私抽取：回复中不得回显用户敏感档案字段

### L5 BadCase 归因体系（缺口⑥，客服方法论平移）

穿搭侧错误五分类（初版，标完再迭代）：

1. **意图理解错**：没读懂诉求（"不要黑色"给了黑色）
2. **知识/档案错**：体型肤色判断错、规则误用
3. **搭配审美错**：色彩冲突/场合不对/风格打架
4. **图文不一致**：文本推荐的单品和生成图对不上
5. **图像质量错**：畸变、衣服没保持、身份丢失

每条 badcase 标注：错误层 / 根因 / 影响面（高频场景？）/ 修复方向（改 Prompt / 改规则 / 换模型 / 补知识）→ 优先级矩阵 → 推动算法侧。

### L6 标注质量管理（JD 标签"AIGC 图像标注质量管理"，缺口⑤）

工业级流水线六环节：

```
POC 试标校准 → 一致性评估(Kappa≥0.85) → AI 预标注+人工初标
→ 100% 交叉复核 → 10%-20% 专家盲审抽检 → 组长争议仲裁
```

- 关键数字/概念：**Kappa≥0.85** 才放量；每批 20-50 条；双标重合部分用于算一致率；错误分级返工；标注全流程可追溯（在编国标《高质量数据集 数据标注要求》征求意见稿三原则：规范统一/质量优先/可追溯）
- **我的诚实说法**："我自己项目里一个人扮演了标注员和仲裁者，双盲+争议标准我都走过；团队化的六环节是我系统学习过的工业流程，上手差的只是带人的经验。"

### L7 评测报告与迭代闭环

- 报告固定结构：版本说明 → 总分与维度分 → 与上版 diff（配雷达图）→ Top badcase 与根因分布 → 自动分 vs 人工分一致性 → **带优先级的改进建议清单** → 回归风险
- 闭环：评测 → 归因 → 给算法侧提改进项（改什么、预期影响哪条 badcase）→ 算法修改 → **同一基准回归** → 对比验证（我的客服项目 McNemar 那套）

### L8 横切层：性能成本 / 多轮 / 线上回流（贯穿全局）

- **非功能评测**：效果好但等 60 秒不可用。我已有现成数据可直接入体系——首调时延 22.08s→15.73s（-29%）、token 3967→3093、单次生成成本≈0.011 元、到手率（受 25s 墙钟影响）。评测报告里效果指标与性能指标并列
- **多轮对话评测**：衣橱顾问、诉求澄清是多轮场景——要评上下文继承（上一轮说"不要黑色"下一轮是否记住）、追问合理性、轮次效率（最少几轮拿到方案）。客服项目的 505 条里已含多轮类用例，可迁移设计
- **线上评测与 badcase 回流**（评测体系活起来的关键）：生产流量定期抽样入评测集；用户负反馈行为（重新生成、不收藏、退出）作为隐式差评信号；每条线上 badcase 修完必须沉淀为回归用例——行业通行原则"黄金集随系统演进而生长"（Braintrust/MatterAI 均建议从 25-50 条起步，稳定集 100-300 条，新失败模式持续补入）
- **评测集分布与样本量**：不能手写拍脑袋——优先真实流量采样，显式覆盖边界/对抗/超纲三类难题；场景×难度×体型做分层配额；样本量按最小可检验效应倒推

- ⚠️ **方法论诚实点**：一个人隔 3 天盲评两轮只能算"自一致性"，**不能冒充标注员间一致性**；主观维度行业标准是 3+ 评分人（我会找 2-3 位朋友对重合样本独立打分：2 人算 Cohen's Kappa、3 人算 Fleiss' Kappa，目标 ≥0.8 锁定标准、≥0.85 才视为可放量；做不到多人时，明确报告里写"单人两轮自评"，不夸大为团队级金标准）

## 五、术语速查表

| 行业术语 | 一句话解释 |
|---|---|
| CP / FITB / CIR | Polyvore 三任务：整套搭不搭（CP，指标 AUC）/ 完形填空选单品（FITB，指标 Accuracy）/ 给一件找搭配（CIR，指标 Recall@K） |
| AUC / Accuracy / Recall@K | ROC 曲线下面积（二分类区分度）/ 命中率 / 前 K 个候选里找回正确答案的比例 |
| MOS | Mean Opinion Score，人工主观分均值，审美评测金标准 |
| CLIP-T / CLIP-I | 图-文本相似度（对齐）/ 图-图相似度（服装保真） |

| ImageReward / HPSv2 / VIEScore | 人类偏好训练的图文美学打分模型 |
| SRCC / PLCC / Kendall | 等级相关系数（SRCC/Kendall）+ 线性相关（PLCC），验证"自动分和人工分排得一不一致" |

| TIFA | 用问答核查生成图是否包含提示词各要素（颜色/数量/关系）的细粒度对齐工具 |
| VTONQA 三维 | 合身度 / 身体协调性 / 整体质量 |
| 对齐/感知/美学 | 文生图评测三维：对不对 / 真不真 / 美不美 |
| Query 改写指标 | coverage 覆盖率、token recall 要点召回、relevance 相关性 |
