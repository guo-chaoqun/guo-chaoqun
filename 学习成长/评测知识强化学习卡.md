## 二、主动回忆卡（10 问，盖住答案先口述）

**Q1 为什么要评测体系？一句话。**
> AI 产出不可控，评测把"感觉不错"变成"可量化、可回归、可验收"。

**Q2 你的 7 个维度是什么？为什么是这 7 个？**
> 意图准确率 / 分支路由 / 答案相关性 / 信息完整性 / 忠实度 / 语气合规 / 边界正确性。
> 来由：从客服业务风险倒推——答错方向（意图）、走错流程（路由）、缺信息（完整性）、编造（忠实度）、得罪用户（语气）、该拒不拒（边界）。

**Q3 505 条用例怎么构成的？**
> 6 大业务分支 × 5 类测试（正常 / 多轮 / 边界 / 对抗 / 违禁）+ 难度分级。**先讲结构再讲数量。**

**Q4 为什么用双通道判分？**
> 规则预检便宜且确定（能机判的先机判），LLM Judge 处理主观维度（相关性/语气）——兼顾成本与准确。

**Q5 LLM Judge 怎么证明它自己可靠？**
> 三件事：①人工盲评抽样校准一致性 ②Judge 三项探针（位置偏置 / 量表遵从性 / 裕度分布）③双序交换实验消除顺序影响。

**Q6 什么是复评基准？解决什么问题？**
> 用同一套评测基准对历史版本重新打分——解决"评测工具自己在变，新旧结果不可比"的污染问题。驱动系统 v1→v3。

**Q7 失败归因怎么做？你归出了什么？**
> 三层失败模型（检索→上下文→生成）逐层排查 → 归出 8 类根因，**72.1% 源自分类器误路由** → 按影响面 × 修复难度排优先级 → 修完复跑验证。

**Q8 18.2 个百分点这个数字怎么来的？**
> 边界混淆场景专项：63.6% → 81.8%（V1 基线 → V3；同口径复评基线为 68.2%）。**追问时补：总体通过率提升用 McNemar 精确检验，b=23/c=9，p=0.02（不是 p<0.01），提升显著、不是噪声。**

**Q9 变异测试是干嘛的？**
> 故意注入 60+ 故障场景，验证断言"该红的会红"——**证明评测体系本身有效**（可证伪性）。

**Q10 从零搭评测体系的 9 步是什么？**
> 定目标 → 定维度 → 建用例 → 选判分方式 → 写 Judge Prompt/Rubric → 跑基线 → 归因 → 建黄金集 → 迭代闭环。

## 三、自造词 ↔ 行业通用叫法对照表

|---|---|---|
| 7 维度评测框架 | 多维评估指标体系 | "我们叫 7 维度，行业里常按 准确性/相关性/忠实度/安全性 分类" |
| 信息完整性 | 完整性 / Completeness | 通用 |
| 忠实度 | **Faithfulness / 忠实度（groundedness）** | "答案是否忠于检索到的知识，不编造" |
| 幻觉率 8.3%→2.6% | Hallucination Rate | 通用，直接讲 |
| 检索未命中明确拒答 | **拒答率 / fallback 策略** | "controlled refusal，防幻觉兜底" |
| 双通道判分 | 规则 + **LLM-as-a-Judge** 混合评估 | "LLM-as-a-judge 是行业术语" |
| 505 条评测用例 | 评测数据集 / golden dataset（测试集） | "评测集构建：收集、清洗、标注、分级" |
| 打分维度标准 | **Rubric（评分标准）** | "我们叫判分标准，即 rubric" |
| 黄金集回归门禁 | **回归测试 / regression set** | 34 例基准集 |
| 复评基准 | 评测一致性 / baseline re-eval | "消除评测工具漂移" |
| 失败归因 8 类 | badcase 归因 / error analysis | 通用 |
| 变异测试 | mutation testing（借自软件测试） | "验证评测体系可证伪" |
| 语气合规 | 安全性 / 合规性（safety） | 归入 safety 维度 |

> **练习方式**：随机指一行，左右两套说法各讲一遍，3 秒内切换。
