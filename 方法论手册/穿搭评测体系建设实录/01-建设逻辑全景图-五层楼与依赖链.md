## 先理清两根轴（最容易混的地方，先看这个）

本体系有两套编号，回答两个不同的问题，**不要互相代入**：

| | 回答什么 | 怎么编号 |
| --- | --- | --- |
| **施工阶段**（批 1→批 5） | 先做什么、后做什么（**时间顺序**） | 批 1 地基 → 批 5 封顶 |
| **评测对象层**（L0–L8） | 产品的哪些部分要被考（**对象切分**） | L0 目标、L1 意图……L8 横切 |

> 关键：一个施工阶段会产出多个对象层的东西（比如"批 3 考卷"阶段同时出 L1/L2/L3 三套考卷）。后文严格区分"阶段"和"L 层"。

## 一、最小心智模型：评测四件套

评测体系 = 四件套，缺一件就是残的：

| 件套 | 是什么 | 穿搭项目的实物 |
| --- | --- | --- |
| **考卷 Dataset** | 一套固定、可复现的题目 | L1 考卷 50 条、L2 回复对 40 对、L3 MOS 卡 34 套 |
| **评分细则 Rubric** | 每题每档怎么打分的书面标准（评分卡） | SOP v1.1 七维、L1 taxonomy（意图分类表）、L2 七维 rubric、L4 图像三层 |
| **阅卷 Judge** | 谁来打分（规则 / LLM 裁判 / 人） | 判分器（规则）＋LLM 裁判（另一个 AI 当老师）＋人工 MOS（多人打分平均分），三通道分工 |
| **及格线 Threshold** | 多少分算过、什么情况直接拦 | L0 一页纸的各层阈值表（H1–H4 否决、七维均分 ≥4.0 等） |

> 反例记忆法：只有考卷没有细则 = 两个人对"显瘦"理解不同，打完全部返工；有分数没有及格线 = 78% 怎么说都行，等于没考。

## 二、五个施工阶段（自下而上，不能跳阶段）

```
              ┌──────────────────────────────────────────────┐
   批 5 封顶   │ BadCase 归因 · 评测报告 · 门禁泛化 · 线上回流    │
              ├──────────────────────────────────────────────┤
   批 4 判分   │ 判分通道 · 三探针校准 · 置信区间 · 冻结基线     │
              ├──────────────────────────────────────────────┤
   批 3 考卷   │ L1 意图50条 · L2 回复对40对 · L3 MOS卡 · L4 图  │
              ├──────────────────────────────────────────────┤
   批 2 标准   │ 七维SOP · L1分类表 · L2评分卡 · L4图像三层      │
              ├──────────────────────────────────────────────┤
   批 1 地基   │ 北极星指标 · 评测边界 · 各层阈值 · 评测频率     │
              └──────────────────────────────────────────────┘
   电梯井（贯穿五个阶段的横切项，不是第六阶段）：
   线上回流 ｜ 性能成本 ｜ 隐私安全 ｜ 诚实口径 ｜ 数据集版本化
```

> 三探针＝裁判上岗前的三项体检（位置偏置／是否按量表打分／分不分得出好坏）；置信区间（CI）＝分数的"把握范围"。

## 三、四句依赖链

1. **先定及格线，再跑分**——阈值先于一切。先跑出 78% 再问"这算好吗"是程序倒置。
2. **先定评分细则，再标注数据**——细则先于标注。标准没定就开标，分歧无法裁决、全部返工。
3. **先建考卷，再配阅卷**——数据先于判分。先写判分器再出题，两者必然对不上号。
4. **跑完基线（冻结的历史成绩单），才有归因和门禁**——基线先于闭环。归因是"和基线比差在哪"，门禁是"比基线掉了就拦"。

行业校验：与 llm-evaluation 六阶段（Define→Datasets→Auto→Human→Gates→Online）逐层同构——**顺序本身就是方法论**。

## 四、L0–L8：九个评测对象层（穿搭产品的实际切法）

> 这是"考产品的哪些部分"，与上面的施工阶段是两根轴。

| 层 | 评什么 | 当前状态（2026-10-14） |
| --- | --- | --- |
| **L0** 目标口径 | 北极星＝方案采纳率 plan_adopt（用户点"采纳"的比例）；边界；阈值；频率 | 🟡 v0.1 待 F1 会议锁 v1.0 |
| **L1** 意图理解 | A 提要求×20 / B 提禁忌×15 / C 乱来×15 | 🟢 基线 v0.1（50 例） |
| **L2** 回复相关性 | 七维评 query→造型师笔记回复对 | 🟢 基线 v0.1（40 对，裁判过三探针） |
| **L3** 搭配审美 | 七维 1/3/5 + H1–H4 硬伤 | 🟡 34 卡×2 轮已渲染，等人评 |
| **L4** 生成图 | 对齐/保真/美学三层次 | 🟠 脚本骨架就绪，图 3/20 |
| **L5** BadCase | 失败案例五分类寄存器（11 条） | 🟡 2 例待仲裁 |
| **L6** 标注质量 | 多个评分员口径一不一致（Kappa 一致性） | 🔴 单人模式：只能报自一致性，Kappa 实操是缺口（标注岗高频话题） |
| **L7** 报告 | 九节报告模板 | 🟠 等 L3/L4 数字回填 |
| **L8** 横切 | 性能/成本/线上信号 | 🟢 成本台账、导购词门禁现役 |

> 为什么没有照抄客服的"意图分类"？本产品**表单即路由、没有独立意图识别组件**——照抄行业模板会评出一个不存在的组件。所以 L1 评产品里真实存在的三件事：自由文本解析（A）、约束遵从（B）、边界处置（C）。

## 五、电梯井（五个横切项，贯穿所有阶段）

| 横切项 | 为什么贯穿全程 |
| --- | --- |
| 线上回流 | 评测集是活的测试合同，badcase 不回流就会过时 |
| 性能成本 | 效果好但等 60 秒＝不可用；实测 50 例全量 ≈0.75 元 |
| 隐私安全 | 真人照片授权、身体意象红线是试穿类产品高危项 |
| 诚实口径 | 单人隔期盲评只能报自一致性；代理指标如实标注 |
| 数据集版本化 | 考卷/裁判/模型版本钉死，静默改基线＝洗白回归 |

## 六、北极星与诚实边界（L0 的两个关键认知）

- **北极星**：方案采纳率 = plan_adopt ÷ 首次生成成功；shopping_add/tryon_submit 只是代理指标，"采纳≠真穿了"的盲区必须写明。
- **没有基线就标"开放项"，不编阈值**。L0 v0.1 里阈值表 7 行只有 5 行有值——诚实缺口比虚假完备专业，这份文档因此敢在。
