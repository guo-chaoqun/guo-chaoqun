# 第一篇 评测是什么：先建立语言

## 1. 一分钟理解"评测"

**生活化解释**：你妈尝菜说"淡了"，这是主观评价；你拿盐度计量出含盐量 0.3%、对照标准 0.5% 判定不合格，这是评测。AI 评测就是把"这个回答/这张图好不好"从第一句变成第二句。

**正式定义**：评测（Evaluation）= 用**预先定义的标准（标准）**、在**有代表性的数据集（考场）**上、用**可重复的方法（裁判）**、给系统输出打出**可比较的结果（分数/结论）**，并据以决策（放行/打回/优化）。

四件套缺一不可：

| 要素 | 通俗说法 | 没有它会怎样 |
|---|---|---|
| 标准 Rubric | 答案的"评分细则" | 每个裁判各打各的，分数没法比 |
| 数据集 Dataset | 一份固定的"考卷" | 每次考不一样，分数涨跌无意义 |
| 裁判 Judge | 谁来打分（规则/模型/人） | 没人阅卷 |
| 判据 Threshold | 多少分算及格 | 不知道改完能不能上线 |

🧪 在我的客服项目里：7 维度评分规则=标准，505 条用例=考卷，规则+LLM 裁判=阅卷，回归门禁=及格线。

## 2. 评测的基本分类（先分清这三组，后面不再混）

**① 离线评测 vs 在线评测**
- **离线（Offline）**：拿一批固定考题在实验室里跑，便宜、可控、可重复——
- **在线（Online）**：系统上线后测真实用户，A/B 实验、点击率、采纳率、留存——最真实但贵、慢、有风险
- 💡 离线负责"筛掉明显差的"，在线负责"确认真实效果"；离线显著提升≠在线一定提升

**② 自动评测 vs 人工评测**
- 自动：代码/模型打分，快、便宜、可大规模；缺点是只能评"写得清标准"的东西
- 人工：慢、贵，但审美、创意、复杂语境只能靠人；行业落地永远是两者配合

**③ 客观题评测 vs 主观题评测**
- 客观：有唯一正确答案（意图分对了吗、违禁词出现了吗）→ 规则即可判
- 主观：没有标准答案（这套搭得美吗）→ 量表+多人一致性

## 3. 评测体系的生命周期

行业通用闭环（学术界称为 Define–Test–Diagnose–Fix 循环）：

```
定标准(Define) → 跑评测(Test) → 找病因(Diagnose) → 修复(Fix)
      ↑                                              │
      └──────────── 同一套基准回归验证 ←──────────────┘
```

每转一圈，系统版本+1，考卷（评测集）也要把新发现的 badcase 补进去——**评测集是活的，不是一次性产物**。

# 第二篇 统计基础：评测的数字语言

## 4. 混淆矩阵：一切分类指标的地基

**场景**：系统判断 100 条用户 Query 里"哪些是要办理退款的"。每个判断有两种结局，2×2 四个格子：

|  | 实际：是退款 | 实际：不是退款 |
|---|---|---|
| 系统判：是 | **TP** 真阳性（判对了）| **FP** 假阳性（误报，冤枉）|
| 系统判：否 | **FN** 假阴性（漏报，放过）| **TN** 真阴性（判对了）|

记忆法：第一个字母 T/F = 判得对不对，第二个字母 P/N = 判成了什么。

📏 四个核心指标：

- **准确率 Accuracy = (TP+TN)/全部**：整体判对比例。⚠️ 数据不均衡时会骗人——100 条里只有 3 条退款，系统全判"否"也有 97% 准确率，但等于没用
- **精确率 Precision = TP/(TP+FP)**：系统报的警里有多少是真的；1−Precision 就是"错杀率"（冤枉好人的比例）
- **召回率 Recall = TP/(TP+FN)**：真的目标里被抓到多少；1−Recall 就是"漏网率"
- **F1 = 2·P·R/(P+R)**：精确率和召回率的调和平均，单值综合两者；P、R 任一很低 F1 就低

🧪 穿搭项目的用法：意图识别评准确率+混淆矩阵；违禁检测（must_not）要**高精确率**（误判用户违规代价大）；漏拒答风险检测要**高召回率**（漏掉违规代价大）。

## 5. ROC 与 AUC：一条曲线一个分

- 分类器往往输出的是"概率/置信度"（0.73 像退款意图），把判定阈值从高到低滑动，每滑一格得到一对（假阳性率 FPR、真阳性率 TPR 即召回率），画成曲线就是 **ROC 曲线**（横轴=误报比例，纵轴=抓到的比例）
- 📏 **AUC = ROC 曲线下面积，范围 0-1**：0.5 = 跟抛硬币一样；0.7-0.8 可用；0.9 很好。它衡量"模型整体把正负样本区分开的能力"，且不依赖你选哪个阈值
- 🏛 Polyvore 的 CP 任务（整套搭不搭）主指标就是 AUC

## 6. 排序指标：推荐/搭配场景专用

穿搭推荐不是判断题，是排序题（给用户的 5 个方案，好的有没有排在前面）：

- **Recall@K**：正确/合适的单品有没有出现在前 K 个候选里（Polyvore CIR 任务指标）
- **MRR（平均倒数排名）**：第一个正确结果排第几名的倒数取平均——排第 1 得 1 分，排第 2 得 0.5，排第 4 得 0.25
- **NDCG（归一化折损累计增益）**：排序界"金标准"，同时考虑①相关程度可以分档（不只是对错）②位置越靠前价值越大③可跨用户/列表比较。直觉：好东西排前面得分高，理想排序的得分做分母归一化
- 💡 区分能力用 AUC，排序质量用 NDCG/MRR/Recall@K。"**

## 7. 相关性系数：自动裁判和人想得一样吗

| 系数 | 评什么 | 取值 |
|---|---|---|
| Pearson（PLCC 的基础） | 两个分数**线性**关系 | -1~1 |
| Spearman（SRCC） | 两个分数**排序**是否一致（只看名次不看差值）| -1~1 |
| Kendall's τ | 同上，另一种算法（数"顺序对"比例），小样本更稳 | -1~1 |

解读（绝对值）：<0.3 弱相关，0.3-0.5 中等，>0.5 较强，>0.7 强。
🧪 图像自动美学分 vs 人工 MOS，行业惯例同时报 SRCC+PLCC：前者证明"排名一致"，后者证明"数值贴近"。

## 8. p 值与显著性检验：提升是不是运气

**生活化解释**：你抛硬币 10 次出 8 次正面，是硬币有问题还是手气好？p 值回答："假设硬币正常（零假设），出现这么极端结果的概率有多大。"
- 📏 **p < 0.05**：概率小于 5%，按惯例认为"不太可能是巧合"，称统计显著
- 常见错误：p 小≠效果大（样本足够大时微小差异也显著）；p>0.05≠没效果（可能样本不够）
- **配对数据用配对检验**：同一批考题前后两版，用 **McNemar 检验**（只看"翻案"的题：前错后对 vs 前对后错）；两批独立考生才用比例 z 检验
- 🧪 我的客服项目：505 题配对，b=23（改对）c=9（改坏），精确 p=0.0201
- 样本量常识：显著不显著与样本量直接相关，正式评测集一般 100-300 条稳定集起步；我 demo 用 30-50 条只能算探索性结论

## 9. 标注一致性：主观题的生命线

多个人给同一套搭配打分，凭什么相信分数？先区分两种需求：

- **分类/打分类一致性**：
  - **2 个标注员** → **Cohen's Kappa（κ）**
  - **3 个及以上** → **Fleiss' Kappa** 或 **Krippendorff's α**（α 更强：支持多人、支持缺失值、支持类别/顺序/连续多种数据，工业界主观标注首选）
  - 📏 原理都一样：κ =（实际一致率 − 碰巧一致率）/（1 − 碰巧一致率）。把"瞎蒙也会相同"的水分挤掉
- **排序类一致性**（让多人把 10 套搭配排序）→ **Kendall's W（0-1）**
- **阈值惯例**：κ/α ≥ 0.8 标准可接受（锁定 Rubric）；**≥0.85 才允许放量给标注团队**；<0.7 说明标准本身有歧义，回去改 Rubric 而不是逼标注员
- **自一致性 ≠ 标注员间一致性**：一个人隔几天评两轮只能查自己稳不稳，不能冒充多人金标准——这是我手册里特意标明的诚实底线

# 第三篇 AI 评测体系：文本、图像、推荐怎么评

## 10. 评测集（考卷）怎么建

### 10.1 构成与分层
- 每条用例三件套：**输入 + 期望输出/标签 + 评分标准引用**
- **黄金集 Golden Set**：从真实场景精选、覆盖核心路径+历史 badcase、规模小而稳定（行业经验 25-50 条起步，稳定后 100-300），用于回归
- **分层设计**：业务场景 × 难度 × 用户类型 交叉配额；三类题必须显式存在——**边界题**（模糊地带）、**对抗题**（恶意诱导）、**超纲题**（知识库没有时该拒答）
- 数据来源优先级：真实生产流量采样 > 人工设计 > 合成数据；纯手写题容易"出题人视角偏差"
- 🏛 标准化参考：在编国标《高质量数据集 数据标注要求》（征求意见稿，编号 GB/T XXXX 占位）提出三原则——规范统一、质量优先、全程可追溯（谁标的、改过几次都要留痕）；引用时表述为"在编国标/行业实践原则"，不要说成已强制实施的国标

### 10.2 LLM 时代的特殊字段
文本类用例除了输入和标准答案，常带：must_not（禁止内容）、expected_points（要点清单）、reference（参考资料/知识库片段，用于忠实度评测）、case_id（跨版本追踪）、difficulty、category。

## 11. 文本评测与 LLM-as-a-Judge

### 11.1 三种判分通道（按确定性排序，能不用模型就不用）
1. **规则**：正则/关键词/结构化校验，100% 确定、零成本
2. **模型裁判（LLM-as-a-Judge）**：处理语义、相关性等规则判不了的
3. **人工**：处理审美、创意、疑难仲裁

### 11.2 Pointwise vs Pairwise
- **Pointwise 单点评分**：一次给一个答案按 Rubric 打分（O(N) 次调用），快，适合批量监控
- **Pairwise 成对比较**：两个答案放一起选优，比较更准但成本高（O(N²)），且有强位置偏置
- 🧪 我的经验：先让模型两边各自独立打 1-5 分再比总分，比直接"选哪个好"稳

### 11.3 裁判的五大偏差（2025 年系统综述归纳，必须会背）

| 偏差 | 表现 | 缓解 |
|---|---|---|
| 位置偏差 Position | 偏爱先出现的答案 | 双序交换、取平均、独立打分 |
| 冗长偏差 Verbosity | 偏爱更长的回答 | Prompt 明确"长度不等于质量"、长度归一化 |
| 自我偏好 Self-preference | 偏爱同模型家族的输出 | 裁判与被评对象用不同厂商模型 |
| 谄媚 Sycophancy | 迎合提问者倾向 | 中性 Prompt，不透露"期望答案" |
| 风格/指令偏差 Style | 偏爱 markdown、格式工整的答案 | 统一输出格式后再评；Rubric 各维度独立判 |

> 📚 最新研究（Judging the Judges, 2025）发现现代模型的风格偏差有时比位置偏差还显著；但**特定提问形态（让模型直接选边）下位置偏差仍可能极严重**——🧪 我实测 8 次调用 7 次选左（87.5%）就是证据，所以不能因为"论文说偏差小了"就不做探针。

### 11.4 裁判可靠性三探针（我的项目标配）
① 位置偏置探针（双序交换统计选左率）② 量表遵从性（检查输出分数是否落在 1-5，我抓到过打 8、9 分）③ 裕度分布（分差全挤在 1 分内=没有分辨力）。
**校准**：人工抽盲评样本，算裁判分与人工分的一致率/SRCC；定期开校准会讨论分歧。

## 12. 图像评测：对不对、真不真、美不美

工业界把文生图质量分三大类，每个自动指标只回答其中一个问题，**不能互相替代**：

### 12.1 对齐（Alignment）——图和要求一致吗
- **CLIPScore / CLIP-T**：把生成图和提示词文本都送进 CLIP 模型变成向量，算余弦相似度（-1~1，通常 0.2-0.4 区间），越高语义越贴
- **VQAScore**：用视觉问答模型核查"图里有没有这个东西"，比 CLIPScore 更擅长组合性描述（"红杯子在蓝盘子左边"）
- **TIFA**：把提示词拆成一串是非问题（颜色？数量？关系？）让 VQA 模型逐项回答，算准确率——适合细粒度核查

### 12.2 感知质量（Perception）——图像本身真实吗
- **FID（Fréchet Inception Distance）**：真实图集和生成图集分别过 Inception-v3 网络提特征，假设特征服从高斯分布，算两个分布的 Fréchet 距离，**越低越好**（越低=越像真实照片的分布）
  - ⚠️ 使用前提：**大样本**（几百到几千张），20-30 张算 FID 没有统计意义；且对小数据集有偏
- **IS（Inception Score）**：又清晰又多样就高分，**但它不看和 prompt 是否对齐**——清晰度 100 分的跑题图也能拿高 IS，已不建议单独使用
- **IQA 类模型**：无参考画质分（清晰度、畸变、伪影），可单张评

### 12.3 美学（Aesthetics）——好看吗
- **LAION-Aesthetics**：在人类评分数据上训练的美学预测模型
- **ImageReward / HPSv2 / VIEScore**：用**大规模人类成对偏好数据**训练的奖励模型，直接输出"人类喜不喜欢"的分——审美自动化的当前主流答案
- 🧪 我的策略：通用对话模型评审美已实证失败（三探针全暴露），重启应换这类偏好专用模型，且必须与人工 MOS 算 SRCC

### 12.4 试穿专项指标
- **CLIP-I**：生成试穿图 vs 用户上传的衣服原图，衡量服装保真度（衣服的颜色款式有没有保留）
- 人工 **MOS 三维**（🏛 VTONQA 数据集确立）：clothing fit 合身度 / body compatibility 与身体的协调性 / overall quality 整体质量
- **身份保持**：面部相似度（做人脸试穿时）

## 13. 搭配/推荐评测：服饰领域的标准答案

- 🏛 **Polyvore Outfits**：真实用户搭配的公开数据集，行业基准（nondisjoint 划分约 5.3 万套训练 + 1 万套测试，另有更严格的 disjoint 划分约 1.7 万套）
  - **CP（Compatibility Prediction）**整套搭不搭 → AUC
  - **FITB（完形填空）**挖掉一件从候选选 → Accuracy
  - **CIR（互补单品检索）**给一件找搭配 → Recall@K
- **关键认知**：Polyvore 的"好搭配"标签来自用户的收藏/共现，是**隐式行为信号不是美学真值**——"搭不搭"至今没有公开标准答案，所以人类 Rubric 不可替代
- **属性本体 Fashionpedia**（CC BY 4.0，可商用署名）：27 服装大类 + 19 部件 + 294 细粒度属性（材质/风格/图案），做结构化标注的标准词表

## 14. 在线评测与 A/B 测试
- 离线指标涨了，最终要在线上用真实用户行为验证：采纳率、二调成功率、重新生成率（隐式差评）、停留/收藏/下单
- **A/B 测试**：流量随机分两组，只改一个变量，对比业务指标；同样要做显著性检验
- 💡 离线→在线的传导关系是评测岗的高阶认知："我为模型负责的离线指标（相关性/忠实度）最终挂在北极星业务指标（采纳率）上"

# 第四篇 服饰领域知识：JD 要的"穿搭审美能力"

> 这一篇补的是行业 know-how。评测服饰 AIGC，你自己得先懂穿搭——否则写不出 Rubric、判不了标注争议。

## 15. 色彩基础（规则层最硬的部分）

- **色彩三属性 HSV**：色相 H（什么颜色，0-360°色环）、明度 V（明暗，加黑加白）、饱和度 S（鲜艳还是灰）
- **标准色相调和**（色环角度关系）：
  - 同色系/邻近色：夹角 ≤30-60°，最安全和谐
  - 互补色：180°，强对比（要靠面积比控制，如 60-30-10）
  - 三角色：120°/240°，活泼
  - 分裂互补：150°/210°，比硬互补柔和
  - ⚠️ 90-150° 是"尴尬地带"——既不协调也没形成明确对比，两件套里最容易丑
- **60-30-10 法则**：主色 60%、辅助色 30%、点缀色 10%
- **感知均匀色彩空间**：HSV 是人按工程习惯切的，人眼对明度变化并不线性；专业场景用 OKLCH/Lab，色差用 **CIEDE2000** 公式（🧪 我项目里用 HSV 差值，手册标注为可升级项）
- **个人色彩诊断（季型理论）**：按肤色冷暖/明度/对比度分春/夏/秋/冬四季、再细分为 12 季型；属商业形象设计体系（源自 Caygill/Carole Jackson），**是通行常识不是学术定理**，引用时说明性质

## 16. 廓形、量感与身形修饰
- **廓形字母论**：X（收腰）、A（上窄下宽）、H（直筒）、O（茧型）、T/V/Y（上宽下窄）
- **量感**：服装给人的视觉体量（小/中/大），由版型松量、材质软硬、图案大小决定
- **扬长避短基本法**：上松下紧/上紧下松制造对比；想遮的部位用深色+合身+简洁；想强调用浅色/亮点；腰线高度决定身材比例观感
- 🧪 我的产品刻意不收集体重、量感只做排序加权不做硬门槛——避免身材评判焦虑，这也是安全设计

## 17. TPO 场合着装原则
Time（时间/季节）、Place（地点）、Occasion（场合）决定着装规范：通勤（正式度高、低露肤）、约会（柔和/精致）、婚礼（喜庆但不盖过主角）、运动（功能优先）。评测"场合契合度"维度时，按 TPO 写每档锚点。

## 18. 风格词汇
常见可用于标签的风格轴：正式度（休闲↔正式）、经典↔潮流、简约↔繁复、柔和↔锐利。中文市场常用风格词（通勤干练/法式优雅/日系复古/美式街头/甜酷/极简高级等）来自商业分类，**无强制标准，自建词表时要明确标注"内部定义"并给正反例图**。

# 第五篇 工程化：标注、归因、安全、项目管理

## 19. 工业级标注质量管理 SOP

```
① POC 试标校准 → ② 一致性评估(Kappa/α≥0.85 才放量) → ③ AI 预标注+人工初标
→ ④ 100% 交叉复核 → ⑤ 10%-20% 专家盲审抽检 → ⑥ 组长争议仲裁
```

- 批次管理：每批 20-50 条给一个标注员（建立上下文、减少错误）；每批抽重合样本双标
- 标注员画像：有人快而松、有人慢而准——后者的产出当"金标准种子"，前者做大规模初标
- 错误分级返工：小错返修、系统性误解回炉培训、标准歧义上升为 Rubric 修订
- 全流程留痕：标注人、时间、修改记录、仲裁结论（可追溯是国标硬要求）
- **Rubric 是活文档**：试标中发现的每一个"两人答案都有道理"的争议，都要回写成一条新锚点或一张正反例图

## 20. BadCase 归因方法
1. 收：从评测结果/线上反馈捞失败样本
2. 分：按错误层归类（穿搭项目五层：意图理解错/知识档案错/搭配审美错/图文不一致/图像质量错）
3. 析：逐层定位根因（是上游理解错、检索没到、还是生成错）
4. 排：影响面 × 修复难度矩阵定优先级
5. 证：修完同一基准回归 + 配对检验
6. 沉：badcase 转回归用例，防止重犯

## 21. 评测报告标准结构
版本与口径 → 总分与维度分（雷达图）→ 与上版 diff → Top badcase 与根因分布 → 自动分 vs 人工分一致性 → **带优先级的改进建议（每条写明：问题/证据/建议改法/预期影响哪些 case）** → 回归风险与放行建议。
💡 报告是给算法/产品侧看的：结论先行，证据可点开，建议可执行。

## 22. 安全与合规（中国境内必须知道）

- 🏛《生成式人工智能服务管理暂行办法》（2023.8 施行）：生成内容不得含违法、歧视、侵权、不实信息
- 🏛 TC260《大模型生成内容安全风险分类体系》：风险评估维度含影响范围、传播性、可逆性、发生可能性——安全评测也是"打分"，思路和效果评测同构
- **服饰试穿专项风险**：真人照片授权与存储加密、不得用于训练、生成图防走光/色情化/未成年人不当呈现、身体意象保护（不得身材羞辱）

## 23. 评测项目管理入门
- **排期**：试标校准 1-2 天 → 正式标注（按人均产能估）→ 复核抽检并行 → 汇总分析 → 报告评审
- **成本意识**：自动判 1 条≈几分钱 API 费，人工判 1 条≈几分钟人力；分层用（自动初筛→人工只看分歧和边界）
- **评测频率与门禁分层**：每次提交跑小集（分钟级）→ 合并前跑中集 → 大版本前全量
- 沟通：评测方与算法方是协作不是对立，改进建议要具体到"改哪个 prompt 的哪句话、预期救回哪几条 case"

# 附录

## A. 指标选择速查表

| 你要回答的问题 | 用什么 |
|---|---|
| 意图分对了几成 | Accuracy（均衡时）/ 看混淆矩阵 |
| 违禁报警准不准/漏没漏 | Precision / Recall（按代价取舍）|
| 分类器整体区分力 | AUC |
| 推荐排得好不好 | NDCG、MRR、Recall@K |
| 整套搭不搭（学术基准）| CP 任务 AUC |
| 自动裁判和人意见一致吗 | Kappa（分类）/ SRCC+PLCC（打分）|
| 前后版提升是运气吗 | McNemar（同批题）/ 比例检验（独立批）|
| 图文一致吗 | CLIP-T / VQAScore / TIFA |
| 衣服在试穿图里保真吗 | CLIP-I |
| 图真不真、有没有畸变 | FID（大批量）/ IQA 单张 |
| 图好不好看 | ImageReward / HPSv2 / VIEScore + 人工 MOS |
| 试穿效果三维 | fit / compatibility / overall MOS |
| 标注团队标准统一吗 | Cohen's κ（2人）/ Fleiss' κ、α（3+人）/ Kendall's W（排序）|

## B. 阈值经验值汇总
- κ/α：0.8 可用、0.85 放量
- p：<0.05 显著
- AUC：0.5 随机 / 0.7 可用 / 0.9 优秀
- SRCC：0.3 弱 / 0.5 中 / 0.7 强（审美任务人-人也才 ~0.42，自动分到 0.3+ 已可做初筛）
- 黄金集：25-50 起步，100-300 稳定；FID 至少几百张才有意义
